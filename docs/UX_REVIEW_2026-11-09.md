# Wayseeker 全站体验走查

日期：2026-11-09。范围：本地工作区当前产品。独立设计评审与技术证据评审分别由两个子 Agent 完成，高优先级探索和复制流程由子 Agent 修复，主 Agent 负责整合、响应式导航、视觉复查与正式构建回归。

后续进展见[第二轮报告](./UX_REVIEW_2026-11-09_ROUND2.md)：下方 UX-08 至 UX-12 已完成实现；UX-13、UX-14 的完成范围、剩余验证与新增 P1 修复在第二轮单独记录。本文保留第一轮发现和当时的证据。

## 结论

百子柜、纸签、真实预览和策展备注已经构成有辨识度的产品语言。主要体验问题集中在找到工具前的选择负担，以及操作后能否确认结果、找回原来的方案。

本轮修复 7 项 P1 问题，并补齐阶段筛选与跳至正文的操作一致性。在已覆盖的路径中未发现 P0；已确认的 P1 均完成修复和复查。剩余工作见下方清单。此结论基于专家走查和浏览器验证，不等同于真实用户研究，也不表示已达到「行业顶级」。

## 已修复的高优先级问题

### P1-01：手机用户获得推荐过晚，缺少快捷入口

原表现：390×844px 触屏模拟下，推荐区域起点约为页面 y=1652px；页头两个分区入口被隐藏。用户必须穿过全部习惯清单，再看到工具推荐。

修复：手机页头保留「找工具」「开方子」；低于 1024px 的单列布局采用渐进展示；手机阶段选择保持两列。相同手机模拟下，推荐区域起点为 y=793px，提前约 52%。这里测量的是推荐区域的几何位置，不是转化率或完成时间。

验收：手机展开可看到全部 29 项，收起恢复少量项；当前项保持可见；两个导航入口均为 44px 高；桌面仍保留完整清单。

位置：`src/components/Header.tsx`、`src/components/Dispensary.tsx`、`src/app/globals.css`。

### P1-02：搜索结果与反馈不一致

原表现：搜索 Mobbin 显示 1 个匹配，但其余 28 个抽屉只是降低透明度，仍占据页面和键盘顺序。

修复：只渲染匹配的抽屉和有结果的列；搜索期间不补空抽屉。没有结果时提供明确说明及恢复全部按钮，清空后焦点回到搜索框。

验收：Mobbin 查询只留下 1 个抽屉、1 列；无结果时不存在无关操作目标；清空恢复 29 个抽屉。

位置：`src/components/Dispensary.tsx`。

### P1-03：详情往返丢失方子与换选

原表现：详情返回链接固定为 `/?tool=…#cabinet`，没有保留 `plan`、`p` 和来源位置。用户比较工具后，无法通过页面入口找回刚调整的方子。

修复：详情链接携带经过校验的首页返回地址；保留方子、换选、选中工具、查询、阶段和分区锚点；同列详情继续传递来源。校验只接受本站首页与允许的参数、锚点。

验收：生成方子、换一行、进入详情、再经同列工具返回后，5 项选择和返回位置不变；拒绝外部或非首页返回地址。

位置：`src/lib/exploration-context.ts`、`src/components/Dispensary.tsx`、`src/components/ToolDetail.tsx`。

### P1-04：复制失败无反馈，图片结果不准确

原表现：详情文字和图片复制异常均被静默处理；图片文案没有反映实际发生的是复制还是下载。方子复制受限时只提示地址栏，无法取出完整 Markdown。

修复：详情展示处理中、成功、错误状态；图片按实际返回值显示「已复制」或「已下载」。文字复制受限时显示原始完整内容，并将焦点和选择放入只读文本框，便于手动复制。方子链接和 Markdown 分别提供对应的回退内容。

验收：模拟剪贴板拒绝后，内容完整、可选择、可重试；PNG 回退产生实际下载，并显示下载结果；切换工具或语言后清理旧状态。

位置：`src/components/ToolDetail.tsx`、`src/components/CopyFeedback.tsx`、`src/components/Dispensary.tsx`。

### P1-05：快捷键修改了无关的屏外推荐

原表现：在方子的换选按钮上按方向键，会改变首页推荐工具，而不是保留当前操作上下文。

修复：方向键与 Home / End 处理限定在首页探索区域；柜体和方子区域保留原生键盘行为。柜体选择后，焦点进入对应推荐标签。

验收：在方子和柜体控件上按方向键，推荐工具不变；从抽屉选择工具后可以继续操作相应详情和访问入口。

位置：`src/components/Dispensary.tsx`。

### P1-06：窄屏工具名被域名挤断

原表现：320px 英文布局中，即使是 TIMING 这样的短名称，也会因同排域名被拆成两行单词片段。

修复：窄屏将名称、域名上下排列，域名允许换行。

验收：320px 中英文标题保持可读；全部 29 个详情页没有横向溢出。

位置：`src/app/globals.css`。

### P1-07：浅色漆面上的键盘焦点对比不足

原表现：印泥红焦点框与浅色模式的漆面背景对比为 2.07:1，低于非文本状态指示常用的 3:1 检查线。

修复：柜体、柜台操作、同列陈列架、页脚使用黄铜焦点框，纸面保留印泥红。

验收：黄铜与浅色漆面为 5.23:1，与深色漆面为 5.97:1。该测量覆盖指定色对，不代表整站所有像素状态均完成对比度认证。

位置：`src/app/globals.css`。

## 验证结果

- `pnpm lint`：通过。
- `pnpm typecheck`：通过。
- `pnpm build`：通过，完成正式静态页面构建。
- `pnpm test`：68 项通过。
- `PLAYWRIGHT_CHANNEL=chrome pnpm test:e2e:built`：33 项通过、1 项跳过；跳过项是桌面项目中不适用的手机展开测试。
- 全部 29 个详情页在中英文、桌面及 320px 手机布局中校验标题、访问链接、横向溢出和页面运行时错误。
- 16 组首页布局 / 主题 / 语言矩阵无横向文档溢出，无 `pageerror`；正式构建未复现开发热更新期间的文案 hydration 问题。
- 原生浏览器结构检查可用，截图返回 `UnknownVizError` 后改用本地 Playwright 截图；没有把失败截图当作视觉证据。

最终机械扫描覆盖本轮修改的 UI 文件，输出 48 条 advisory：字阶 38、颜色 8、圆角 2；没有非 advisory 结果。这些是与 DESIGN.md 声明匹配的提示，不能直接当作 48 个体验缺陷。初始全源扫描为 46 条 advisory，两次目标范围不同，不用于计算改善率。浏览器检测器的 1 条嵌套卡片提示，经核对是既有「漆面托盘承载纸签」结构，属于误报。

设计系统同步记录本轮筛选、响应式、返回与复制约定，未扩大为视觉重设计。

## 验证边界

本轮完成浏览器模拟和专家走查，未开展真人可用性研究、实体手机测试、Safari / Firefox 回归或真实 VoiceOver 听读。未逐一验证第三方站点自身的服务质量。上述范围以外的结论需要下一轮证据，不能用页面无报错替代。
