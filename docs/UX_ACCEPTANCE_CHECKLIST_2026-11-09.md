## 状态定义

| 状态 | 可以据此得出的结论 | 所需证据 |
| --- | --- | --- |
| implemented | 代码或可执行材料已交付 | 对应文件和行为约定；不代表实际设备验证 |
| browser-evidence | 指定浏览器、构建、条件中的行为已验证 | 自动化结果、截图或浏览器记录，说明模拟和实际平台 |
| needsrealdevice | 仍需实体设备、系统输入法、原生权限或实际辅助技术 | 设备/系统/浏览器版本、步骤、实际结果、证据位置 |
| needshumans | 仍需符合招募条件的真实参与者 | 同意、任务记录、实际观察及原话；不能用 Agent 评分替代 |

状态可并存。例如 UX-11 已 implemented 且有 browser-evidence，但实际 VoiceOver 顺序仍为 needsrealdevice。空白记录表示未执行，不表示通过。不适用必须写明具体设备和原因。

## 完成口径

- 开发闭环：有对应实现、文档和当前构建的浏览器回归，且未留下已确认的核心阻断。
- 设备闭环：DEVICE-01、AT-01、INPUT-01、NATIVE-01 均有实际设备证据，不能用模拟器或 DOM 存在性代替。
- 用户体验验证闭环：完成已同意的研究任务并汇总真实观察；发现的新问题仍按严重性进入下一轮，不保证「三个参与者都成功」才能结束。
- 无法取得设备、参与者或可访问构建时，保留具体缺口、下一步和负责人。已准备执行包可以交付；不能因此宣称真机或真人研究已完成。
