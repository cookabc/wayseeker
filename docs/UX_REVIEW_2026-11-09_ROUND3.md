## 结论

本轮发现并修复 5 项 P1，集中在复制恢复、异步导出和 URL 与界面的一致性；另修复 3 项 P2：印章透明层撑宽页面、长查询刷新前后不一致、组合输入时 Escape 误清空。

用户现在可以看到并操作手动复制内容；字体请求长时间不结束时仍能导出；尝试新方子、切换语言或返回首页后，旧复制请求不会把过期反馈塞回当前界面。浏览器尚未完成原生复制时，界面明确显示等待，并提供主动选择的手动复制。

本轮属于浏览器模拟和专家走查，未开展真实用户研究。既有页面在失去网络后仍可进行部分本地操作，不代表产品已提供完整离线模式。

| P1-12 | 先启动图片、再复制文字，文字已成功后，较早的图片操作仍会覆盖剪贴板 | 同一详情页的文字和图片复制共用同步互斥锁，避免同帧重复激活；原生复制未结束时不再发出另一项复制 |

| P1-14 | 在带筛选和方子的首页点击品牌或页脚「首页」，URL 已变为 /，界面仍保留原筛选和五项工具，刷新前后结果不同 | 增加局部路由观察，外部同路径导航恢复对应状态；内部 URL 更新不重置操作。后退、前进恢复匹配状态；仅分区片段变化仍保留撤销 |

异步导出同时补齐取消边界：字体准备、PNG 编码、原生复制返回和下载之前检查任务有效性。切换工具或语言后，旧请求被拒绝也不会触发过期文件下载。

## 六个维度

| 维度 | 本轮重点 |
| --- | --- |
| 信息架构 | 等待说明和手动复制入口就近放在导出操作之后，不增加弹窗或全页阻塞 |
| 用户流程 | 首页重置、历史恢复和旧请求完成都遵循当前上下文，不向新方子回填旧内容 |
| 操作效率 | 原生复制互斥避免重复请求；长时间等待后可主动取出当前文本继续操作 |
| 反馈机制 | 区分仍在等待、成功、真实拒绝；不把超时谎报为失败，也不在权限提示尚未处理时自动下载 |
| 视觉层级 | 手动恢复字段进入可见视区；透明动效不再扩大手机页面 |
| 组件一致性 | 详情和方子均采用等待提示、同步互斥、过期反馈抑制；共用恢复字段的原生选择和焦点规则 |

## 弱网与断网证据

Chrome DevTools Protocol 模拟：390×844，400ms 网络延迟，下行 50,000 B/s、上行 25,000 B/s，CPU 4 倍降速；英文和中文各一次冷启动。此配置是人为定义的限速条件，不代表真实运营商网络或实体手机。

- 首次有内容绘制约 8.3 秒；共享方子恢复约 10.6 秒。没有页面运行时错误。
- 图片迟迟未返回时，工具名、访问链接、搜索和围绕当前工具开方仍可使用；最终失败后出现预览不可用说明。
- 页面加载完成后断网，搜索、开新方子、撤销及取出 Markdown 仍可使用。未声称未缓存页面导航或刷新可离线完成。
- 字体永不返回的导出采用确定性 Promise 探针复现；权限延迟采用受控剪贴板 Promise；没有用真实权限窗口自动确认来伪造成功。
- 冷启动资源记录显示，一份渲染阻塞 CSS 约 68KB 传输、186KB 解压后体积，约 8.1 秒完成；字体及脚本也竞争限速带宽。需要独立优化首屏资源，不能将导出等待修复当作首屏性能改善。

本地证据目录：.impeccable/review/2026-11-09-r3/，包含弱网指标、资源时间线、越界定位和渲染截图。
