## 招募与安排

| 代号 | 招募条件 | 使用方式 | 重点观察 |
| --- | --- | --- | --- |
| P01 | 未使用过 Wayseeker，近期需要寻找创作、设计或开发工具 | 本人常用桌面浏览器 | 首屏能否理解、入口选择、推荐依据 |
| P02 | 未使用过 Wayseeker，平时会在手机上寻找和保存工具 | 本人实体手机与常用浏览器 | 推荐到达、滚动、触摸、复制与返回 |
| P03 | 有日常键盘导航及屏幕阅读器经验，愿意使用熟悉的辅助技术 | 本人常用设备、浏览器和读屏；优先招募 VoiceOver 使用者 | 独立操作、状态朗读、焦点与恢复 |

每人约 30–40 分钟为本方案建议安排，不是产品任务耗时标准。若未能招募有读屏经验的参与者，保留该席位并标记未执行；开发者临时打开 VoiceOver 的测试另记为设备检验，不能代替 P03。不要因参与者操作慢而排除记录。

招募文本：「我们正在观察一个寻找创作工具的网站是否容易理解和使用。希望邀请你用平时习惯的设备完成几个任务，说明哪些地方清楚或困惑。研究对象是网站，不是你的能力。无需提前学习，也不要求完成所有任务。」招募、预约及补偿安排由研究负责人执行；本文件不代表已联系任何人。若提供补偿，应事前说明并与任务是否成功无关。

执行前填写：负责人 ______；站点可访问地址 ______；构建/提交标识 ______；日期 ______；补偿安排 ______；资料访问者 ______；资料删除日期 ______。删除日期和用途必须在同意前确定，不借用产品隐私政策推断研究规则。

## 同意与主持口径

先口头说明并取得明确同意：「今天观察的是网站。你可以跳过任务、暂停或随时退出，无需解释。我们会记录操作与反馈，用于改进产品。不会要求真实账户密码、私人文件或向别人发送内容。你是否同意参与？是否另外同意录制屏幕和声音？不同意录制也可以继续，我们只记匿名笔记。」

同意记录：参与代号 ______；参与同意 □是 □否；屏幕录制 □是 □否；音频录制 □是 □否；记录时间 ______；撤回/删除联系方法已说明 □。拒绝参与则结束，不填写任务表现。不把不同意录制算作失败。关闭通知、私人标签页和无关应用后再开始；使用代号，不在共享报告记录姓名、账号或联系方式。

开场：「请按你平时的方式使用。可以说出你正在找什么、期待发生什么，以及让你犹豫的地方；不必一直说话。我通常先观察，不会立即告诉你点哪里。任务没有规定操作路线。」

主持人可以问「你现在在想什么？」「你觉得刚才发生了什么？」「下一步你会怎么做？」。避免问「这个按钮是不是很清楚？」「你看见上面的开方子了吗？」。参与者问「应该点哪里」时答「如果你独自使用，会怎么尝试？」。需要救助时先记下时间、卡点和原话，再提供最少帮助，并将任务记为协助完成。

参与者提出停止、出现私人内容、持续不适或明显疲劳时立即暂停。连续约 2 分钟没有进展可中性询问是否愿意继续；这个时长是主持提示，不是硬性失败阈值。停止后仍可讨论原因，不强迫坚持。

## 场景与任务卡

三位参与者都执行 T1–T3；选择个人熟悉的界面语言。使用未带搜索和方子参数的首页开始 T1，记录初始语言、主题与视区。T2、T3 延续同一会话，不提前清除参与者的成果。主持人只读任务卡，验收观察点留给记录者。

### T1 找一个合适工具

读给参与者：「你准备做一个新项目，想先找到一款能帮助你收集或组织界面灵感的工具。请在这个网站上找一款你愿意尝试的，并告诉我它为什么适合、需要注意什么。如果觉得没有合适的，也可以说明原因。」

观察：能否理解网站用途，自选入口，找到工具及其用途、替代做法和限制。请参与者指出依据，允许不同合理选择；不以选中指定工具作为成功条件。不要提前提示搜索、阶段、抽屉或标签的位置。

完成条件：参与者作出有页面依据的选择，或基于现有信息解释没有合适选项。仅随意点击后说「完成」仍需记录理解不足。任务后问：「你对这个选择有多大信心，1 是完全没把握，5 是很有把握？为什么？」

### T2 比较后回到原处

读给参与者：「你想再看一款类似用途的工具，比较后回到刚才的浏览位置继续选择。请按你平时的方式完成。回来后告诉我，你是否还知道刚才看了什么。」

观察：进入详情、找到可比较对象、辨识差异、返回后能否确认原来的查询/阶段/工具。允许使用浏览器返回、页面返回和新标签页；分别记录路径，不暗示其中一条更正确。观察者在任务前记下当前 URL 与选中工具，不把这些答案告诉参与者。

完成条件：查看第二个工具并说出至少一个有依据的差异，返回原来的浏览上下文，能继续原任务。若自主打开新标签页成功完成，应计为独立成功并记录所用策略。任务后问：「回来后的页面符合你的预期吗？哪里让你确认或怀疑？」

### T3 导出可再次打开的方子

读给参与者：「你想把一组工作流程建议留到稍后继续使用。请在网站里准备一组方案，调整其中一项，再保存成你能在本机带走的文字。最后请验证：重新打开你保存的地址，仍能看到同样的选择。无需真正发给任何人。」

观察：能否发现生成、理解五阶段与推荐依据、区分单行调整和重开、取出完整文字及可复现地址。记录者在导出前记下五项工具与 URL；让参与者在本机空白文本编辑器粘贴，使用本机新标签页验证地址，不要求外部发送。

完成条件：实际粘贴得到有五项选择的完整 Markdown，保存的地址可还原相同五项；仅显示成功通知不算导出证据。若原生权限被拒绝，可自主使用手动文本恢复；这种恢复成功照常记录，同时标记原生拒绝。任务后问：「你觉得这些推荐为什么放在一起？」「你有多大信心稍后能找回，1 到 5 分？」「刚才最需要你反复确认的地方是什么？」

若要观察重开撤销、权限拒绝或图片下载，在三项核心任务后另做探索：询问参与者是否愿意再试一种情况，不计入 T1–T3 的独立成功率。不得事前代替参与者处理权限窗口。若当前浏览器不能展示真实拒绝场景，记录未覆盖，不用注入 Promise 冒充真人体验。

## 指标与判定

| 指标 | 记录方法 |
| --- | --- |
| 结果 | 独立成功 / 协助完成 / 未完成 / 主动跳过；协助包括方向或控件提示 |
| 耗时 | 从读完任务且参与者准备开始，到达到任务条件、放弃或中止；暂停与技术故障单列，不悄悄扣减 |
| 完成率 | 独立成功人数 ÷ 实际尝试人数，同时列原始人数，例如 2/3；跳过与未尝试另列，不用 3 人推算总体表现 |
| 误操作 | 与当时意图不符且需要纠正的操作；普通探索和合理换路不算错误。记意图、动作和恢复成本 |
| 协助 | 次数、发生时点、原文提示；提示后的成功不回写为独立成功 |
| 认知负担迹象 | 重复寻找、反复返回、读错状态、不能解释推荐；记行为与原话，不诊断参与者能力 |
| 情绪与信心 | 每任务 1–5 分及解释；记录犹豫、挫折、释然的直接表达，避免从表情推断心理 |
| 理解 | 能否用自己的话说明用途、限制、推荐依据及保存后的恢复方式；区分观察事实与研究者解释 |

问题按用户后果排序：P1 阻断核心任务或丢失成果且没有可发现的恢复；P2 能恢复但造成重复、误解或明显犹豫；P3 不妨碍任务的局部细节。单次严重事件也可立项；不因只有一个人遇到就忽略。跨 3 人的次数用于定位共性，不代表发生率。

## 实体设备与 VoiceOver 独立验证步骤

此部分是执行规程，尚未填写结果。执行者记录真实设备，不用 Playwright 的 WebKit、iPhone 视区或可访问性树替代实际朗读证据。浏览器模拟已有的结果见第三轮报告。

前置条件：使用待验收构建的可访问地址；浏览器安全上下文支持所测剪贴板功能；准备本机空白文本编辑器；获得录屏/录音许可。使用测试内容，关闭私人通知。记录系统、Safari、VoiceOver 语音与语言、文字缩放、减少动态设置、网络和构建。权限状态需记原值，测试后按执行者原偏好恢复。

1. 在实体 iPhone 的「设置 → 辅助功能 → VoiceOver」启用读屏。先确认执行者能熟练使用左右轻扫、双击激活、转子；系统名称或手势随版本变化时按设备实际设置记录。Mac 的真实 VoiceOver 可作补充，不能代替 iPhone 检验。
2. 用 Safari 从干净首页开始。通过转子的标题和链接浏览，记录主标题、找工具、开方子、语言/主题入口及跳至正文的可达性。每次停留的可访问名称与可见名称应对应，不出现无法理解的无名按钮。
3. 逐一切换工具和阶段，记录实际播报原文或音频时间点。期望只就必要变化宣布工具和阶段，不重复整张标签或打断当前输入；记录是否延迟、重复、漏读。随后继续前进，确认能到达详情和访问入口。
4. 用实体设备中文输入法输入搜索词，再在确实有组合候选时取消组合；外接键盘可另测组合中的 Escape 和普通 Escape。记录输入法名称、是否仍在组合、按键以及查询变化。软键盘没有 Escape 时写不适用，不能写通过。
5. 进入详情并经同列工具返回。通过读屏焦点和目视双重确认原搜索、阶段及方案未丢失，固定页头未遮挡当前操作。分别记录页面返回和浏览器返回。
6. 生成、换一行、重开并恢复上一张方子。记录实际焦点落点、标题朗读和五项是否恢复。切换分区后检查仍可恢复；刷新后检查明确的失效约定。不要把静态 DOM 顺序等同于焦点或朗读顺序。
7. 允许一次文字复制，再粘贴到本机空白编辑器，比较当前语言与完整内容。若系统真实出现权限请求，记录选择与结果。能实际拒绝时验证恢复文本框可找到、位于可见区域、可触摸选择、可由 VoiceOver 定位并复制。无法产生拒绝时写未覆盖。
8. 原生请求若实际长时间等待，确认等待提示未自动移动焦点，再主动取出手动文本并粘贴。若未出现长等待，记录未覆盖；已有受控 Promise 测试属于浏览器证据。
9. 尝试图片导出。根据设备真实能力分别确认已复制后可粘贴，或已下载且能在文件/下载位置打开 PNG；检查中文、英文与长名称完整。没有发生下载时不能仅凭通知写成功。
10. 在 iPhone Safari 和 Android Chrome 分别检查正常滚动、触摸、文字放大、旋转与系统减少动态。用真实受限网络记录条件和可见反馈；已加载后断网检查可用操作，另测刷新并如实记录，不能推断完整离线支持。
